# v0.6.18

В журнале реального PB617 после поворота в 0.6.17: sdk=1024x758, qt=758x1024, window=1024x758. Уведомление QPA было поставлено в очередь; успех означал лишь наличие экспортированной функции, а не изменение границ. Предыдущий тест с qWait скрывал задержку в XCB.

ScreenGeometry::synchronize вызывает экспортированный flushWindowSystemEvents(ExcludeUserInputEvents) в GUI-потоке перед перерисовкой. Затем сравнивает фактические geometry и availableGeometry с требуемыми; hook=1 в журнале теперь означает их совпадение. Пользовательский ввод при этом не прокручивается. Приватные поля Qt и прошивка не изменяются.

Регрессионная проверка требует правильных размеров сразу после вызова, без обработки обычного цикла событий. На старой реализации она воспроизводит неверный размер; на новой проходит. Интеграционная проверка покрывает четыре ориентации, сохранение XPointer и возврат в библиотеку без реальной записи в аккаунт.

Сохранено пожелание пользователя: новая регистрация значка по умолчанию помещается в «Пользовательские»; уже выбранная группа сохраняется. Авторизация, кэш и позиции чтения при установке не меняются.

Визуальный результат на прошивке pocketbook2 требует проверки после отключения USB. Диагностика screen sync позволяет проверить применение размеров на устройстве.

Проверка на PB617: размеры Qt действительно совпали с SDK во всех ориентациях, но пользователь подтвердил, что текст всё ещё обрезается. v0.6.18 не опубликована как релиз; далее проверяется прямой вывод страницы через SDK.
