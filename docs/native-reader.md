# Native FB3 reader (v0.6.15)

The standard LitRes library remains in WebEngine. A main-frame HTTPS navigation to `/static/reader/text/index.html` opens `NativeReader`; its menu can explicitly open the web version instead.

`ReaderTransport` uses a separate, blank HTTPS page in the existing authenticated profile. It fetches metadata, the TOC and only the current/next listed FB3 part. Text is not executed as JavaScript. `Fb3Data` parses a limited, bounded data-only JSON5 subset. `Fb3Layout` preserves text anchors and UTF-16 offsets (excluding soft hyphens), uses native QTextDocument line layout, and clips only complete lines. Page turns start at the first line not shown on the preceding page; no line is repeated or skipped. Main paragraphs are justified, and author-centered/right-aligned blocks retain their alignment. Backward page history stores text anchors; changing the font or orientation repaginates from the current anchor. Font size is remembered. Raster illustrations use native image objects with their own XPointer anchors; they are scaled to fit a complete page and preserve their aspect ratio. The transport fetches only image filenames listed in the FB3 nodes, using the same authenticated cookies. Chromium decodes raster data once and normalizes it to bounded PNG (maximum 758×1024) so the firmware does not need a JPEG plugin. Native image decoding rejects invalid or oversized data. The reader preloads pictures near the viewport, releases distant document image resources and bounds its decoded-image cache to 8 MiB. Left/right arrows have no reading action; physical paging keys and up/down control text, OK opens the menu, Back returns to the library.

Progress uses the observed `/foundation/api/users/me/arts/{art}/fb3/autobookmark` API. On opening, GET restores the server pointer. Local records under `native-reader/{user}/{art}.json` contain only bookmark state, not credentials or book text. Writes wait five seconds after the latest page/line movement and are serialized, use the last server version plus one, and retain pending changes during network failures. A changed server position or HTTP 409 blocks automatic overwrite. The user chooses the local or remote position. Acknowledgements cannot clear a later local edit. Explicit logout removes native reader state before removing the authenticated profile.

Last-book history is written only after a visible book part opens successfully. Each account has its own `native-reader/{user}/last-book.json`, containing only the book ID/title and opening time. Pressing LitRes verifies the active user before showing a plain-text Yes/No prompt. Yes opens a fresh reader, re-fetching metadata, TOC and the server bookmark; No opens My Books. Existing pending local progress is retained and the normal conflict policy still applies. The first book opened after upgrading establishes the history; there is no guess based on older bookmark file timestamps.

Limitations: this implementation supports normal FB3 text and raster illustrations. EPUB, DRM and unsupported resource formats use the explicit web fallback. No decryption or access-control bypass is implemented. TOC/part reads must succeed using the user's existing session. Footnote navigation, cloud conflict behavior on a second physical device and e-ink timings remain future/device checks.

## Validation

- ARM EABI5 soft-float app compiled using the cached builder and existing firmware Qt libraries (`--pull=never`).
- `tools/tests/native-reader.cpp`: strict data parsing, parent/inline XPointer round trips, complete line coverage for nine width/font combinations, offline state, conflicting versions, edits during save and ambiguous network results. Optional private chunk argument validates real text anchors without committing book content.
- Isolated native Qt test opened an authorized real book using GET/OPTIONS only, restored the current remote pointer, and produced a native rendering. A request interceptor blocked all network writes. The same transport serialized/acknowledged a POST through a mocked `fetch`, with zero network POST requests.
- `reader-images-history.cpp`: portrait, landscape and square illustrations retain proportions and fit in 24 viewport/font layouts, full line coverage with images, stable text/image anchors, durable history, validation and account isolation.
- `reader-resume-ui.cpp`: real MainWindow Yes, No and other-account paths against a synthetic API; fresh cloud position supersedes an old synchronized local record; JPEG passes through the real Chromium binary transport and PNG normalization, then native rendering. Network writes are blocked. Browser teardown is checked after the reader closes.
- Tests do not demonstrate actual PB617 e-ink latency or a live cross-device write/read cycle. Those require reading on the device; the real cloud bookmark was not moved by test traffic.

A generic Linux Qt test build:

```
g++ -std=c++11 -fPIC tools/tests/native-reader.cpp -Isrc $(pkg-config --cflags --libs Qt5Widgets Qt5WebEngineWidgets) -o /tmp/native-reader-test
QT_QPA_PLATFORM=offscreen /tmp/native-reader-test
```

No cookies, private signing keys or book content belong in repository fixtures.

Image/history tests use only generated artwork and synthetic book data. Compile `tools/tests/reader-images-history.cpp` with Qt5Widgets and `-Isrc`. The UI test includes the application and writes its fixed PocketBook data paths; run it **only in a disposable container**, never against an actual mounted reader. Its desktop SDK stubs are in `tools/tests/stubs/inkview.h`. Link Qt5Widgets, Qt5WebEngineWidgets, Qt5Test and the two existing Monocypher C objects. Arguments `yes`, `no`, `other` exercise each branch. No account credentials or copyrighted fixtures are required.

## Offline books and reconnect (v0.6.15)

An authorized book is saved in the background under `native-reader/{user}/books/{art}`. The cache stores a bounded JSON manifest, strict JSON parts and normalized raster images. It follows the TOC and image filenames, never guesses resource URLs. Content writes are atomic; caches are separated by user and edition. A previous edition is archived instead of mixed with new fragments. A denied resource response invalidates offline access rather than falling back to cached content after a server denial. A transport error can open the prior authorized cache. At least one part must have been saved; full availability is advertised only after all parts and listed raster images are saved. A 20 MiB free-space reserve pauses the background downloader. Reopening cached parts uses disk, not a network round trip. Distant decoded images are released; only a small text window and an 8 MiB image cache stay in memory.

With Wi-Fi disconnected, LitRes offers the last cached book using its local bookmark; No opens a native list of saved books. Reading never waits for the network. The active user marker is remembered only after a successful identity request, and logout clears it with the account's private reader data. While reading offline, connection is checked every 15 seconds. Reconnect checks identity, edition and a real TOC response before resuming background downloads/sync. Offline changes retain their original server baseline. A conflict still requires choosing a position; writes cannot silently overwrite newer remote progress. The unchanged remote/local path uploads the pending local position, then acknowledges the returned version. Local state persists immediately on navigation; normal server writes wait 5 seconds of inactivity. Manual retry/exit can flush sooner. Every write verifies the current account; the retry loop cannot post an old account's progress after a login switch. Background progress repaints only the footer.

## Rotation, updates, launcher and covers

The reader menu calls SDK `SetOrientation`, cycles portrait → 90° → 180° → 270°, remembers the preference, resizes to SDK screen dimensions and reflows from the same text anchor. The original orientation is restored when returning to the library or closing the app. Global firmware orientation settings are not changed. Desktop integration tests use SDK stubs; the real PB617 QPA/physical button behavior still needs on-device confirmation. The stacked window does not inherit the hidden home screen's portrait minimum height in landscape mode.

Update notes use a read-only, scrollable QTextBrowser so long notes cannot push Install/Cancel off screen. Page keys scroll notes, Up/Down move between the text and buttons, OK selects the action. Website adaptive covers are constrained to a relative frame with an explicit natural-aspect height, keeping them alongside the description; other page images are not globally positioned.

The icon in `assets/app-icon.png` was adapted from the user's supplied logo with imagegen and packaged as an embedded 120px grayscale BMP (`LauncherIcon.h`). On first launch the app writes the icon and merges only its own `U_litres` entry in the user partition's `system/config/desktop/view.json`, preserving other entries/groups and saving a backup. No `/ebrmain` firmware files are written. Only a regular `._litres.app` file with verified AppleDouble magic/version is removed; ELF files, unknown files and symlinks are preserved. Reopen the Applications screen after first launch so the launcher can refresh its icon/name.

New validation: `reader-offline.cpp` tests complete text/image caching, restartable 5-second sync, local offline reopen, cross-part offline paging, reconnect upload and another offline reopen through actual Qt/Chromium against a synthetic API. `reader-storage-ui.cpp` tests cache persistence/account isolation/edition invalidation, launcher merge/backup/duplicate safety and long update notes with keyboard scrolling. `browser-cover.cpp` recreates the detached cover and verifies its natural-aspect frame beside the text in Chromium. The updated resume UI test exercises all four SDK orientations, preserves the bookmark through resizing, and restores orientation on Back. Existing line-coverage tests now assert that no line appears on two consecutive pages and that paragraphs are justified. No real cloud bookmark is moved by these fixtures. Run UI/integration tests only in a disposable container, never against mounted reader data.
